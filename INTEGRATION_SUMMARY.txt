     const { addChild } = useBitacora();

         nombre: 'Juan',

         fechaNacimiento: '2015-05-20',
         edad: 9,

         grado: '4° Primaria',
         foto: 'https://example.com/photo.jpg',
         historia: 'Historia del niño...',
         suenos: 'Sueños y aspiraciones...',
         situacionFamiliar: 'Situación familiar...',
         necesidades: ['Material escolar'],

       console.log('Niño creado:', child);
     };
   }

⚠️  NOTAS IMPORTANTES:

1. ENDPOINT URL:
   El código asume que el backend expone: /kafka/{topic}
   Si tu backend usa otra ruta, edita api-client.ts línea 176:
   
   async sendToKafka<T>(topic: string, payload: any) {
     return this.post<T>(`/kafka/${topic}`, payload); // ← Cambiar aquí
   }

2. USER ID:
   El userId se obtiene del user.id (AuthContext) y se convierte a number.
   Si tu sistema usa otro campo, edita BitacoraContext.tsx línea 295:
   
   const userId = user?.id ? parseInt(user.id, 10) : 0;

3. FOTOS:
   Actualmente se esperan URLs de fotos.
   Si necesitas subir archivos, implementar endpoint separado.

4. FALLBACK A MOCK:
   En desarrollo, si el backend falla, se usa mock data automáticamente.
   Para producción, considera remover o loggear estos fallbacks.

5. TOKEN:
   El token se lee de localStorage.getItem('token').
   Asegúrate de que tu AuthContext lo guarde allí al hacer login.
